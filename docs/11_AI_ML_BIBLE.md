## 1. What AI Does in CIVIX

| Task | Layer | Who does it |
|---|---|---|
| Parse raw CDR fields | Source → SourceRecord | Parser (deterministic) |
| Extract entities from text | Observation → Extraction | NLP model |
| Match faces in CCTV | Evidence → Extraction | CV model |
| Infer ANPR plate | Evidence → Extraction | CV model |
| Detect communication anomalies | Extraction → Assertion | Anomaly detection |
| Propose identity candidates | SourceIdentity → Candidate | Clustering/similarity model |
| Generate investigative leads | Hypothesis → Lead | Graph ML |

**AI does NOT**:
- Create hypotheses (human only, DB CHECK enforced)
- Confirm hypotheses (human only, DB CHECK enforced)
- Self-confirm leads (human disposition required)
- Write to Neo4j directly (outbox pattern enforced)
- Train on production data (generation_run_id filter enforced)

## 2. Model Provenance

Every AI-derived row (extraction, identity_candidate, assertion) must trace to exactly one `analysis_run`:

```
analysis_run:
  model_name: "CIVIX-NLP-v2"
  model_version: "2.1.3"
  algorithm_parameters: { threshold: 0.70, language: "hi" }
  input_snapshot_hash: sha256:...  (hash of input dataset)
  input_snapshot_tx_time: 2026-08-01T00:00:00Z  (AS-OF timestamp)
```

This allows:
- Reproducibility: same inputs → same outputs
- Auditability: "why did the AI say this?"
- Version control: "this lead was generated by model v2.1.3, not v3.0"

## 3. Preventing Future Data Leakage

Training data must only use information available at the training snapshot time.

```sql
-- Correct: feature extraction for a model trained on August 1, 2026 data
SELECT * FROM civix.assertion
WHERE tx_start <= '2026-08-01T00:00:00Z'
  AND (tx_end IS NULL OR tx_end > '2026-08-01T00:00:00Z')
  AND generation_run_id IS NOT NULL;  -- only synthetic training data
```

The `input_snapshot_tx_time` field on `analysis_run` is mandatory to prove when the snapshot was taken.

## 4. Confidence Thresholds

| Level | Threshold | Action |
|---|---|---|
| Low confidence | < 0.70 | Creates `data_quality_issue`. Does NOT create assertion. |
| Medium confidence | 0.70–0.90 | Creates `extraction` + `assertion(epistemic_status=POSSIBLE)` |
| High confidence | > 0.90 | Creates `assertion(epistemic_status=PROBABLE)` |
| Human-confirmed | — | `assertion(epistemic_status=CONFIRMED)`, `decided_by` set |

## 5. Graph ML Features

Neo4j is the source for graph-based ML features:

| Feature | Neo4j Query |
|---|---|
| Call frequency between P1 and P2 | Count `[:PARTICIPATED_AS {role:'CALLER'}]` edges via events |
| Network centrality | PageRank on `[:PARTICIPATED_AS]` graph (SUPPORT edges only) |
| Community detection | Louvain on `[:PARTICIPATED_AS]` graph |
| Temporal communication pattern | Time-series of event timestamps per entity pair |
| Financial flow | Sum of transaction amounts along `[:TRANSFERRED_TO]` paths |

**All graph algorithm queries must filter**: `WHERE stance = 'SUPPORT'`
CONTRADICT/NEUTRAL/INCONCLUSIVE stances are stored as properties on `[:HAS_STANCE]` but excluded from structural traversal. (ADR-015)

## 6. Synthetic Data Isolation

```
civix.generation_run — tags all synthetic rows
civix.scenario — holds ground_truth JSONB (NEVER projected to Neo4j)
civix.dataset — GOLDEN_WORLD | SYNTHETIC_TRAIN | SYNTHETIC_VAL | PRODUCTION
```

Production analytics: `WHERE generation_run_id IS NULL`
Training analytics: `WHERE generation_run_id IS NOT NULL`

**These two populations must NEVER be mixed in any ML pipeline.**

---

## 7. Explainability Requirements

Every investigative lead generated by AI must include an `explanation` field:
- What data triggered this lead?
- Which assertions contributed?
- What was the AI confidence?

This is not optional — it is required for investigators to decide whether to pursue the lead.
